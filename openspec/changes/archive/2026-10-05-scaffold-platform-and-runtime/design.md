## Context

The challenge must run locally and be judged on decisions as much as features. The architecture is microservices (ADR 0001), so foundations must be shared without coupling domains.

## Goals / Non-Goals

**Goals:**
- One command to run; no `.env` required.
- Identical error, logging and health behaviour in every service.
- Database isolation per service from day one.

**Non-Goals:**
- Hot reload inside containers (local `pnpm dev` covers it).

## Decisions

- **Monorepo with pnpm workspaces and Turborepo.** Atomic changes across contracts and services and lean images through `pnpm deploy`. Alternatives: Nx (heavier), polyrepo (needs published packages).
- **`packages/platform` for technical code only** (ADR 0010): config validation, logging, problem+json filter, request ids, migrations runner, health, messaging. Domain code never lives there. Alternative: copying the code per service, rejected because it creates four copies of subtle reliability code.
- **node-postgres with plain SQL migrations applied at boot** (ADR 0002), under an advisory lock and recorded in `schema_migrations`. Alternative: Prisma, rejected because of pnpm client collisions and native engines on Alpine.
- **Request ids** are generated by Fastify when missing (`x-request-id`), echoed on every response, and logged by pino on every line.
- **Errors** are always RFC 9457 problem+json with a stable `code`, `correlationId` and optional `errors[]`. Unknown errors become 500 `INTERNAL` without stack traces.
- **Gateway** is NestJS on Fastify with `@fastify/http-proxy` (streaming), `@fastify/rate-limit` buckets and `@fastify/helmet`. nginx serves the SPA and proxies `/api` so the browser sees one origin.
- **One parameterized Dockerfile** (`ARG SERVICE`) for all Node services: multi-stage, non-root, `tini` as PID 1.

### Alternatives considered

| Option | Trade-off |
|---|---|
| Single all-in-one container | Literally "a docker container", but contradicts the service boundaries |
| nginx or Traefik as the API gateway | Faster, but problem+json errors and correlation logic would need extra modules |
| `@nestjs/throttler` | Proxied routes bypass Nest guards, so limits would not apply |

## Risks / Trade-offs

- [More containers than a monolith] → health-checked startup ordering and a measured cold start of about 30 s.
- [Fixed local credentials] → documented as local-only; no secrets are required.
